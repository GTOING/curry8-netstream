# 当前执行任务快照：P4-B ONNX 分期—Rally API 启停联动

快照日期：2026-09-20。

> 本文件供对应执行人员直接领取任务。动态权威队列仍为 [`decision_records/ACTIVE_QUEUE.md`](../decision_records/ACTIVE_QUEUE.md)；如果两者后续出现差异，以权威队列的最新内容为准。执行人员完成后提交事实报告，不在本文件建立第二套项目状态。

## 目标

在现有 Windows 控制器中，把实时且有效的 ONNX 睡眠分期结果与 Rally 当前已加载刺激协议的启动/停止联动：

- 标签属于用户选择的目标睡眠期：请求 `Start Stim`。
- 标签不属于目标睡眠期：请求 `Stop Stim`。
- 不使用低电流、低频率或其他“静默协议”。
- 本批只负责当前协议的启停，不选择、切换或修改具体电刺激范式；范式与睡眠期的映射后续另行安排。

## 已确认的 Rally 接口

- UDP 请求端点固定为 `127.0.0.1:8801`。
- UTF-8 启动命令：`Start Stim`；精确成功回复：`启动刺激成功`。
- UTF-8 停止命令：`Stop Stim`；精确成功回复：`停止刺激成功`。
- Rally 会从 `127.0.0.1` 的动态 UDP 源端口回复，回复端口不一定是 `8801`。接收端必须允许动态源端口、校验源主机为本机、记录实际端口并设置有限超时。
- 可兼容现有成功回复 `RALLY_ERROR_SUCCESS`，但任意非空回复、超时或无法解码的内容均不得判为成功。
- 2026-09-19 已在远程实验电脑人工验证 API 能实际启动和停止 Rally。本地参考文件为 `reference/RallyStartStopTest.py`、`reference/START_STOP_TESTING.md` 及原始 `reference/RealtimeControl*.py`；这些未纳入本任务快照的测试/原始材料仍只作为本地证据，其中的固定参数和时间线不是执行合同。

## 必须实现的行为

1. **分期结果资格**：仅当前实时会话、当前连接、`ProcessingStatus.SUCCESS`、合法标签 `W/N1/N2/N3/REM`、新鲜且块序单调递增的 ONNX 结果可作为正常睡眠期决策依据。无效标签、失败、取消、不可用、过期或其他不合格结果（包括 `NoModel`）不能触发 `Start Stim`，也不能被当作新的正常目标期/非目标期结果；当前会话的合同既定故障另按第 8 条保护性收尾。回放、离线 NPY、历史结果以及其他 session/generation 的结果不得改变当前控制状态或触发任何控制命令。
2. **目标期设置与默认隔离**：复用 GUI 的目标睡眠期多选；目标集合默认空，真实 Rally 自动控制默认关闭。每个应用会话都需用户显式确认后启用。默认未启用真实控制的场景（包括默认 `NoModel` 和回放），不论收到何种分期结果，均为零真实请求。显式启用后的基线 `Stop Stim`、用户关闭自动控制/会话退出时的保护性 `Stop Stim`、以及启动结果不确定后的单次补偿 `Stop Stim` 是独立控制动作，不受分期资格过滤的零请求规则禁止。
3. 目标期对应期望运行，非目标期对应期望停止。同向重复结果不得重复发送命令。
4. 至少实现 `DISARMED/UNKNOWN`、`STOPPED`、`STARTING`、`RUNNING`、`STOPPING`、`FAULT/UNKNOWN` 状态。只有精确成功回复能更新“最后确认状态”；发送成功不等于设备状态确认。
5. 每次启用真实自动控制时，先发送一次 `Stop Stim` 建立基线。只有停止得到明确确认，才允许后续分期触发启动。
6. 任一时刻最多一个 Rally 请求在途，不创建无界队列；请求完成后按最新合格分期重新决策。停止、断开和退出优先于启动。
7. 启动被拒绝、回复未知或超时时，不重试启动；执行一次有界补偿停止，关闭真实自动控制并标为未知，直至停止被明确确认。
8. **故障停止路径**：仅当前实时 session/generation 中、真实控制已启用的会话故障（包括模型失败、Curry 断流/断开、块序中断，或运行中切换到不可用/`NoModel`），以及该控制会话中用户关闭自动控制/断开会话/正常退出应用，才走此收尾路径。设备未被确认停止时，执行一次有界保护性 `Stop Stim`；该停止是故障/关闭收尾，不是由无效标签推导出的睡眠期刺激决策。设备已确认停止时不重复发送。停止未获明确回复时显示 `FAULT/UNKNOWN`，提示操作者从 Rally/硬件侧独立停止，不得伪造“已停止”。回放、离线、历史或其他 session/generation 的迟到结果（包括错误）不得改变当前控制状态，也不得对当前或新会话触发 `Start Stim` / `Stop Stim`。
9. 真实 Rally 与现有模拟器模式互斥；首批真实模式只允许 `127.0.0.1:8801`，不开放任意远程地址。回放只能展示历史控制事件，不能重发。
10. GUI 清楚显示当前控制模式、期望状态、最后确认状态、最近命令/回复、关联分期/块号/模型、时间戳及故障提示。软件按钮不得描述为硬件急停。
11. 通过现有 session 单写者追加控制事件，不改写原始 EEG。记录控制模式、事件类型、分期标签、块号、模型标识、目标集合、命令、发送/接收时间、回复原文、回复主机和动态端口、状态转换与结果类别。

## 不在本批范围

- 不调用或改写 `RealtimeControlAPIDemo1...5.py` 来切换协议。
- 不移植 `RealtimeControlManager.py` 的固定实验时间线。
- 不决定 N2、N3 等睡眠期分别采用哪套刺激范式。
- 不冻结最少持续 epoch、置信度阈值、刺激持续时间或正式同步方案。
- 不执行受试者实验，不把 API/自动化测试成功解释为刺激安全、物理输出或科研效果已经得到证明。

## 实现约束

- 复用现有分期、刺激策略、传输层、GUI 和 session 单写者，不新建平行框架。
- 保留 P3 回环模拟功能与测试；仅在用户显式启用真实模式时放开固定本机 Rally 端点。
- 传输层保存原始回复和实际来源；未知、拒绝、超时与迟到回复按失败处理，不循环重试。
- 保留 Rally/硬件的独立停止方式并写入运行说明。程序异常终止不能被当作可靠停止手段。

## 验证与完成标准

- 单元测试：结果资格、目标映射、状态机、幂等、单请求、停止优先、断流/模型失败/关闭，以及启动不确定后的单次补偿停止。明确断言不合格结果不能触发 `Start Stim` 或形成新的正常睡眠期决策；当前启用会话的既定故障在设备未确认停止时走一次保护性停止。
- 假 UDP 端测试：动态回复端口、两条中文精确成功回复、兼容成功回复、拒绝、未知回复、超时、迟到回复、非本机来源。
- 集成测试：合成 Curry 数据 → 真实 ONNX 或受控分期结果 → 假 Rally → GUI 与 session 事件，并分别断言：默认未启用真实控制 + 无效结果为零请求；当前已启用实时会话发生模型失败且停止未确认时恰有一次保护性 `Stop Stim`、没有 `Start Stim`；旧 session/generation 的失败/取消/过期迟到结果不改变新会话状态且不发命令；回放不发命令。显式启用时的基线停止、用户关闭/退出停止和启动不确定补偿停止应按各自场景验证，不计入“分期不合格结果零请求”断言。
- 完整回归：保留既有安装、ONNX、记录/回放、P3 模拟和 GUI 行为。
- 自动化通过后，实验人员才在无受试者、刺激协议已人工检查、独立停止可用时做限界真机验收：基线停止 → 目标期启动 → 重复目标期不重复启动 → 非目标期停止 → 故障/关闭停止。每步分别核对 Rally 回复、Rally 界面和物理输出。
- 交付实现、测试、运行说明与事实报告。报告分别陈述代码/测试证据、Rally 回复证据、物理输出证据；未验证项必须明确保留。
