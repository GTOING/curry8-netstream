# 现代化控制台 UI：一轮开发计划

日期：2026-09-25。设计依据：[调研与设计基线](../../docs/P_GUI_MODERNIZATION_DESIGN.md)。正式平台 Windows，保留 PySide6 QWidget 与现有采集／刺激／记录功能。本轮在 `feature/modern-control-ui` 分支开发，完成后由主线程验收，再决定是否合并；现在不创建分支、不改 GUI 源码。

## 顺序与交付

1. **设计落地核对**：执行者从最新 `main` 创建 feature 分支，先核对现有公共 UI 状态入口与所有业务信号，将设计基线落成页面结构和关键状态样图／线框；检查 800×600 与 1000×720 的空间、实际中文文案、故障提示。只在有明确价值且许可兼容时考虑第三方组件；首选原生 Widgets＋作用域样式。
2. **分块重组**：优先建固定运行栏与四个浅层页面，复用 `MainWindow` 当前对象、signal／slot 和状态更新；再统一排版、色彩、焦点与禁用态。只改变展示和操作可达性；不改 Curry、ONNX、Rally、SessionWriter/Reader 合同。动态状态文本由真实已有信息生成。
3. **交互验证**：以真实 Qt 事件验证键盘、滚轮、焦点、点击和可访问状态；用合成 Curry 与随机本机假 Rally 核对默认零请求、显式启停和回放零请求。保留原功能测试，最终完整回归。输出默认、800×600、真实模式故障、回放与长文本截图和事实报告；Windows 桌面有条件时再做原生视觉／缩放验收。
4. **主线程验收与后续决定**：先审功能与错误语义，再审视觉与 Windows 证据。功能、布局或设备前提未满足时留在 feature 分支收口；通过后再由用户决定提交／推送、PR 和合并。任何验收均不把模拟 API 回复当作物理刺激证明。

## 完成标准

- 固定运行栏回答实时／回放、Curry、模型、Rally API 确认和记录状态；故障与自动控制关闭入口可达。
- 四页面职责明确，首次使用者无需在长滚动页寻找核心动作；800×600 无遮挡或无法操作的控件。
- 默认 NoModel、真实控制关闭、记录／CSV 关闭；回放只读，导航或绘制不发包；Issue 8 防误触保留。
- 现有 `MainWindow` 与 controller 接线、旧会话、数据路径和控制语义不回归；完整测试实际通过，限制如实记录。
