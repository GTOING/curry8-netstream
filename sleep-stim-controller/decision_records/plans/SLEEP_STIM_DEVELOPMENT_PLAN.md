# 睡眠分期电刺激控制器开发流程

日期：2026-09-15。状态：主线程规划，尚未发布工程执行任务。

依据：[需求整理](../../docs/SLEEP_STIM_REQUIREMENTS.md)、[参考资料分析](../../reports/2026-09-15_reference_review.md)、[开发目录](../../README.md)。

## 1. 开发顺序与交付目标

先形成可以接收、显示和回放脑电的桌面程序，再接入分期接口与刺激决策，最后接入真实模型、Rally 和时钟同步。模型或设备暂缺时，以明确标识的测试替身验证工程流程，不把替身输出当真实分期或实际刺激。

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5。模型和 Rally 的外部资料可在 P1–P3 期间补齐；真正接入各自组件时分别满足依赖，不要求所有外部材料同时到位才能开发界面。

| 阶段 | 主要交付 | 完成标准 |
| --- | --- | --- |
| P0 接口与状态约定 | 数据、分期、刺激、会话记录的最小合同；首版 UI 信息结构 | 接口能支持缺模型/缺设备开发；未定实验参数明确为空，不以 Demo 代填 |
| P1 桌面框架与 EEG 接入 | 可启动 GUI、Curry 后台接收、通道绘图、连接和错误状态 | 合成数据通过真实接收入口展示；GUI 不被收包阻塞；可结束线程并关闭窗口 |
| P2 分期接口与可追溯记录 | 30 秒块校验、模型适配入口、分期结果显示、会话记录与回放 | 输入块、输出分期、时间与异常可关联；离线回放可复现输入和处理结果 |
| P3 刺激策略与 Rally 适配 | 五期多选、策略判断、UDP 构造/解析、模拟 Rally 联调 | 能解释每次发送或不发送原因；超时与不确定结果明确；停止语义有区分 |
| P4 真实接入及时间同步 | 真实 Curry 数据、真实模型适配（提供后）、Rally 联调、同步实现 | 分别有真机证据；采集/推理/请求/响应/实际刺激时间可区分，误差可测量 |
| P5 首版收口 | 完整使用流程、安装说明、相关回归、实验前验收记录 | 可复现安装；故障和退出行为符合合同；明确工程与实验有效性的证据边界 |

## 2. P0：最小合同

主线程在工程任务发布前给出以下定义，集中在少量接口文档中，不预建复杂框架。

### 数据与模型

- 复用 Curry DataBlock；控制器层补充会话标识、块标识、采样范围、接收时间等关联字段。
- 每个输入块包含通道标签、采样率、数组布局与单位声明。实际通道和采样率由目标配置确定，不固定五通道或 250 Hz。
- 30 秒块校验与异常处理由接入层统一执行；不能默默补零、裁剪、拼包或改变单位。若实际服务器分块不同，由主线程根据抓包明确组块规则。
- 模型接口拟包含加载、预测和释放；预测输入为已验证的块，输出包含 W/N1/N2/N3/REM 或明确不可用/失败状态，以及模型标识。置信度仅在模型实际提供且含义明确时显示。
- 模型未接入时显示“未接入”，不默认 W；测试替身仅供测试或显式演示模式使用。
- 预处理、重采样和通道选择的归属待模型资料确认，避免接收端和模型端重复处理。

### 刺激与状态

- 分开表示用户启用自动控制、目标期选择、策略决定、请求发送、Rally 响应和实际设备状态。
- API 调参会停止当前刺激再启动新协议，不能把“每个目标期数据包”直接映射为重复调参。
- 明确“暂停自动决策”“结束数据接收”“停止实际刺激”的区别，按钮最终命名和行为写入合同。
- 启停和状态接口未确认时，不能把停止进程、关闭 socket 或低幅值方案显示为设备停止成功。
- 规划采用单一刺激命令执行者，避免 UI、定时器和分期线程同时写设备；不沿用每个动作起一个子进程的旧调度方式。

### 界面与会话

- 界面拟展示连接、模型、分期、目标期、刺激状态和错误信息；图表数按实际选定展示通道决定。
- 数据接收、推理和刺激通信在后台，Qt 主线程负责界面更新；缓冲有界，处理落后必须可见，不能无限排队后按过期结果刺激。
- 会话记录拟关联原始/解码数据、配置快照、分期结果、策略决定、命令与响应。格式、保存开关与容量在 P2 前确定，不提前指定全部 EEG 永久保存。
- 本地日志可以记录单调时钟和墙钟，采样时间保留独立来源；这只是取证基础，不声称跨设备已同步。

## 3. P1：可运行桌面与数据接入

实施范围：从 UI 模板提取界面组件到正式包，保留原模板；连接参数、连接/断开、状态提示、通道波形；在后台复用 CurryClient。必要时局部修复断连结果、可取消等待和退出资源回收。

验证：以相称的合成 TCP 服务或现有测试辅助覆盖握手、完整块、半包超时、断连和退出。验证窗口缩放、设置滚动、错误可见性及通道 X 轴关联；macOS 原生窗口与离屏测试分别记录。此时不接真实刺激。

首个里程碑：用户可以启动窗口、接收并查看脑电，知道当前是否连接成功及数据是否有效。

## 4. P2：分期接口、记录与回放

在 P1 基础上建立推理调用链。未提供模型时只交付接口和测试替身；提供后再写具体适配，不开展训练。

每个块关联一次明确的处理状态，错误或不支持的输入不能产出伪造分期。记录处理耗时与积压情况。对延迟结果、无效块及断连后的旧结果，按主线程合同决定丢弃/显示/禁止刺激，不能静默用于当前刺激。

确定会话格式后复用既有读写能力，补充最少的读写/回放代码；回放默认不向真实刺激端发送命令。

验证：30 秒长度、通道/单位检查、模型缺失和异常、连续块关联、记录读回、回放顺序、晚到结果。测试验证行为，不重复为每个字段写镜像测试。

## 5. P3：目标期策略和 Rally 模拟联调

用户多选目标睡眠期，策略模块依据合同决定是否发送刺激请求。实际触发粒度、冷却时间、最短稳定期等均不在本计划中擅设数值。

从 Demo 复用 RealTimeControl 字段、编码规则和错误码，重构为可调用适配器；目标地址可配置，接收有超时，未知响应和设备拒绝有明确信息。

用受控本地替身验证成功、错误码、无响应、迟到响应、来源不符、重复决策与切换。请求执行不确定时不得无条件重发，因为 Rally 可能已重启刺激。控制器内部关联号不能凭空改变供应商线协议。

独立设备停止接口未取得时，只完成可证实的调参和停止自动发送行为，实际设备停止保持不可用/未确认状态；不因此阻塞纯策略和模拟联调。

完成标准：合成 EEG/分期输入可以经过真实策略与报文代码到模拟 Rally，记录完整。报告明确标记模拟链路，不能写“真实闭环已验证”。

## 6. P4：真实设备、模型与同步

### 实际接入顺序

1. 在用户提供目标配置和采集授权后，验证 Curry 至少两个连续 30 秒真实数据块的形状、标签、单位、采样连续性及保存后解码复现。
2. 模型提供后验证真实输入的形状、预处理与输出映射，记录耗时；工程推理成功不等于分期准确性获得支持。
3. 确认 Rally/固件版本、初始刺激协议、地址与设备启停接口，按明确授权范围联调。示例参数不得自动成为实验配置。
4. 收齐同步相关代码/接口后实现同步。确定参考时钟、刺激标记来源、时间映射、延迟和误差测量方法及验收阈值。硬件条件不足时明确只能观测请求/响应时间，不能把它们替代实际刺激时刻。
5. 在分别验证组件后，按授权进行端到端联调，记录 EEG 块、分期、策略、Rally 请求及设备事件。

已有 PPT 的 W3/W4 接线照片仅提供参考，不能直接作为 Curry 8 同步设计。

## 7. P5：首版验收与交付

- 验证正常启动、配置、接收、分期、控制、暂停/停止与关闭流程。
- 覆盖断网、模型失败、Rally 拒绝/无响应、数据积压、错误参数以及刺激状态未知时的产品行为。
- 执行与改动相关的集成和回归，保留实际结果，不因每个阶段都结束而机械重复全套测试。
- uv.lock 安装复现、目标操作系统运行、文档与日志入口清楚。
- 交付清晰区分：软件完成、模拟联调完成、真机验证完成、同步误差已证实、实验效果支持程度。
- 是否打包分发、初始化主 Git 仓库或发布远端，在用户要求下另行处理。

## 9. 主线程与执行线程协作

主线程先完成当前阶段所需最小合同，再准备限界执行 prompt，由用户分发。执行线程负责实现和验证，回报改动、实际命令、结果与剩余问题；主线程验收并维护唯一队列。没有自动创建任务或调用子代理。

每次任务按可独立验收的阶段切分；不为目录、普通局部修复或测试失败再建额外审批流程。发现改变研究/实验语义的选择时，先完成独立部分，再提交具体待决项。

当前建议下一步：完成 P0 最小接口与首版 UI 信息结构设计，然后发布 P1 执行任务。此计划本身不触发工程实施。
