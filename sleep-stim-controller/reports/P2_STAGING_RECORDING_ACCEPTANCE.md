## 阻碍验收的问题：实时 pending 块可进入离线回放显示

静态调用路径明确如下：

1. 实时会话接收有效块并放入 controller._latest；在下一次 100ms UI 轮询之前会话完成断开/EOF，pending 仍保留（P1 为展示最后一块而有意保留）。
2. controller.set_replay_active(True) 只修改模式布尔值，未清除/隔离 pending；window.set_replay_mode(True) 只清除图表。
3. app.py 的 poll_timer 不区分实时与回放模式，继续执行 pump_latest → controller.take_latest_block → window.show_block。
4. ui.py 的 show_block 依据 _replay_mode 把任何传入数据标为“离线回放”，且该分支优先于 historical。

因此打开另一会话（或空会话、回放加载尚未完成）时，可把上一实时会话的最后一块标成所选会话的回放；若回放结果先显示，曲线还可能被旧实时块覆盖，导致数据和结果来源不一致。违反 P2 合同第 4/6 节的会话隔离与只读回放语义。

本轮仅做静态路径核对，未执行专门运行复现。现有回放联调测试未强制制造“实时 pending 尚未消费即切入回放”的顺序，不能排除此路径。

修复要求：在应用/控制器模式边界隔离实时绘图交接，保证进入回放后不消费或展示旧实时 pending，退出回放后也不会重新冒出旧块。保留 P1 正常断开后查看最后有效块的行为。方法由执行者选择，不需重建双状态机。

必要验证：复用现有合成与会话 fixture，暂停绘图轮询以确定性保留实时 pending，结束实时会话，再经正式打开回放接线加载不同样本范围的会话，手动触发泵/恢复定时器，断言曲线、block_id、样本范围和结果均属于所选回放。覆盖空/加载失败回放不会显示旧实时块，以及退出回放后的状态。新增测试用于上述实际竞态，不机械扩大测试矩阵。
