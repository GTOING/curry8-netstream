# P4 接入准备与后续真机阶段边界

日期：2026-09-16。依据：[开发计划](../decision_records/plans/SLEEP_STIM_DEVELOPMENT_PLAN.md)、[P3 验收](../reports/P3_STIMULATION_SIMULATION_ACCEPTANCE.md)、[需求](SLEEP_STIM_REQUIREMENTS.md)。

## 本次发布决定

用户要求发布 P4。现有材料尚不足以冻结真实设备控制和跨设备同步语义，将 P4 分批发布：本次 P4-A 处理原生 macOS 启动 139 的诊断、证据支持的局部修复及真机接入准备；后续批次在主线程取得相关资料、明确范围后单独发布。P4-A 完成不代表 P4 真机阶段完成。

## P4-A 工程范围

1. 比较当前 uv/Python/Qt 环境、最小 QApplication 与正式入口的原生启动和关闭行为，定位既有 139。记录命令、退出码、有关日志、Qt 平台及可用的本应用崩溃栈。系统 GUI 错误只是线索，不能据此直接判定根因。
2. 允许必要的局部启动、生命周期、依赖或运行说明修复；修改必须基于复现证据。保留标准启动命令，不用默认 offscreen、吞掉错误、后台残留进程或禁用业务组件伪装修复。无证据不升级/降级整套依赖，不为此默认引入打包系统。
3. GUI 可访问时验证正式入口原生窗口的默认状态、800×600 控件可访问性、窗口关闭和进程退出；原生窗口无 EEG 曲线是默认正确状态。联网验证限现有合成 TCP 与应用拥有的随机端口 UDP 模拟器，测试模型继续只在测试注入。
4. 基于现有接口整理后续接入操作与证据要求，形成简明 runbook 和缺失资料表。复用 P1/P2/P3 接口，不提前建立真实传输开关、通用设备框架或另一个会话格式。

## 保持的合同

P1/P2/P3 的数据语义、单写者、回放隔离和默认 NoModel 保持不变。自动决策默认关闭，参数无实验默认值，正常入口仅能发送至应用拥有的模拟端。不得接入已有 Rally、8801、真实 Curry/设备或受试者，不执行原始 Demo，不开展模型训练或模型效果验证。

不实现同步映射、刺激开始/停止确认或实际输出控制；本机单调时间只能说明本进程观察到的事件。请求发送/响应时间不替代实际输出时间，普通软件联调不证明分期准确性或同步精度。

## 后续批次所需资料与判定

| 后续范围 | 必要输入 | 完成后可支持的结论 |
| --- | --- | --- |
| Curry 真机接收 | 目标机器/版本/端点、输出通道/采样率/单位、采集与数据保存授权 | 至少两个连续 30 秒块的解码、连续性与保存复现；具体执行次数由该任务明确 |
| 真实模型接入 | 用户提供模型包、输入输出/预处理合同与样例 | 加载与推理工程兼容、耗时；不自动证明准确性，模型本体/训练仍不在开发范围 |
| Rally/设备控制 | 软件/固件版本、部署地址、初始协议、实际参数限制、实际触发策略、启停/状态和确认接口及联调授权 | 指定条件下的请求与设备观察结果；不能用退出 Python 或低幅值协议代替停止确认 |
| 同步 | 参考时钟、可观测硬件事件/标记来源、同步代码/接口、测量方法和允许误差 | 有独立观测证据的时钟映射与误差；缺硬件事件时只能报告软件时序 |

这些输入由主线程与用户明确。执行者列出事实与最小缺项，不代选实验参数；缺项不阻塞原生诊断和文档交付。

## 验收

提交可复核的原生诊断、相关修复与验证事实、接入 runbook。若宿主 GUI/工具权限阻塞，记录实际限制、未验证项及最小用户桌面复现命令；完成其余范围，不能宣称原生问题已修复。原生通过需要真实窗口观察和关闭/进程结束证据，offscreen 仅验证相应工程路径。

改代码/依赖时实际完成 uv sync --locked、相关验证与最终 P1/P2/P3/Curry 完整回归；纯文档交付只检查文档，不为凑结果重跑测试。历史 139 和已有报告保持原样，以新报告记录后续发现。
