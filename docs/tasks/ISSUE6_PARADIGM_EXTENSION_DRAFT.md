在同一正式仓库、同一控制链增量支持版本化范式包。读取 [Issue 6 完整快照](../../reports/remote_issues/2026-09-22/issue-6.md) 与 [Issue 5 合同](../ISSUE5_RALLY_ARMING_CONTRACT.md)。保留现有二值模式，不能复制第二套 UDP/生命周期状态机；原始 Demo/Manager 仅作只读协议来源。

## 后续具体实施路线

1. 增加通用范式配置加载/验证层，一次读取全部协议，规范化 JSON、版本及内容哈希。验证引用、有限数值、通道子集、返回通道不可修改、基础协议兼容。运行期只消费冻结快照，不执行 Demo 子进程或 builder。
2. 在现有请求类型和 worker 上增加 RealTimeControl，复用单请求、动态回复端口、总 deadline、隔离 socket、Stop 保留额度与独立控制租约；不能开并行协议请求通道。
3. 停止态 ACTIVATE(X)：Start 明确成功后立刻 ApplyProtocol X，两步都成功才 RUNNING(X)。运行中切换直接 RealTimeControl X，不先 Stop。实际已发送命令失败/未知后一次保护性 Stop，禁止自动重试。
4. 一次只保留最新 desired；在途 A 后先 B 后 C 跳过 B。启动/切换中出现 Stop 需求不继续旧 Apply 链，按有界结果执行 Stop；默认启用零命令。
5. SD 到期撤销运行确认，不因同阶段重复结果隐式续期。到期恢复条件须先由补充合同明确，不自行以超时推断物理已停止。
6. SessionWriter 存完整范式/协议快照而非路径，记录基础协议与人工确认、模型与通道、各阶段结果、期望/no-op/请求/回复/动态端口、epoch/决策/发送/确认时刻、维持时长。回放只展示。
7. GUI 展示当前范式版本、desired 协议、API 确认协议、在途/故障/到期，避免两步未完成就显示正在运行目标协议。
