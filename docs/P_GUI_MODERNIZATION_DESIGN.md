# 控制台现代化界面：调研与设计基线

日期：2026-09-25。适用基线：`main@c636c244e89e785af75134dc711d48b5d051976b`。这是下一轮 GUI 设计依据，不改变已实现的采集、模型、Rally 或会话合同；实现与合并另行验收。

## 1. 现状与设计目标

当前界面是 PySide6 `QWidget`，默认 1000×720，最小 800×600。顶部固定连接与错误区，主体用一条长 `QScrollArea` 放数据摘要、模型、刺激、记录回放、Curry 参数和诊断。视觉上大量状态混在句子里；真实控制的期望、API 确认、物理未验证和故障信息不易一眼区分。默认截图见 [P-GUI](../reports/P_GUI_DEFAULT.png)、[回放](../reports/P_GUI_REPLAY.png)、[800×600 会话区](../reports/ISSUE7_SESSION_CSV_800X600.png)。

本轮目标是使操作者在数秒内回答四个问题：**当前是实时还是回放？Curry/模型在做什么？自动控制是否启用、Rally 最近确认了什么？本次记录是否完整？** 主要操作不依赖搜索长页面；故障和关闭自动控制的入口始终清晰。视觉基调为克制的 Windows 实验控制台，不做波形、拟物仪表或装饰动画。

## 3. 信息架构与布局

使用保留 Qt 原生窗口标题栏的单窗口结构。顶部固定“运行栏”，下面以 `QTabWidget`／等价原生导航呈现四个浅层页面；同一状态由现有 UI 状态入口驱动，不建立第二套控制状态。页签文字优先，不用只有图标的导航。

```text
┌ 睡眠分期电刺激控制器 ─ 实时/只读回放 ─ Curry 连接状态 ─ 连接/断开 ┐
│ 30 秒接收进度  │ 模型/最新期别 │ 自动控制模式 │ Rally API 确认 │ 记录状态 │
│ [持续可见的错误/未确认停止提示；完整内容可展开或复制]               │
├ 运行总览 │ 刺激控制 │ 记录与回放 │ 连接/模型/诊断 ┤
│ 当前页面内容：按任务组织；次级内容可纵向滚动                     │
└ 会话 ID / 数据来源 / 当前操作反馈 ───────────────────────────────┘
```

1. **运行总览**：当前 30 秒窗口 `已收到/30 秒` 与块号；模型可用性、最新真实期别／无结果原因；目标期集合和最新期别明确分开；最近控制事件、期望状态和 API 最近确认状态以独立字段呈现。无数据、NoModel、失败不能显示伪期别。EEG 波形仍只在 Curry 8 查看。
2. **刺激控制**：模拟／真实模式与二值／范式档案的明确分组；目标 W/N1/N2/N3/REM 多选、触发策略和无预设数值输入；真实模式的协议／范式来源、操作者确认、启用自动控制分步呈现。启用后“关闭自动控制”始终在固定区域可达，只调用现有停用路径，不能标成硬件急停。模拟端相关控件仅在模拟模式出现。冻结配置仍可阅读，不能通过导航解除锁定。
3. **记录与回放**：实时记录及自动 CSV 两个独立默认关闭选项、当前保存目录和状态；离线打开／退出、前后块导航、CSV 重建。回放使用明显的“只读／不会发送命令”标题；不与实时控制画面共用含糊的启动按钮。路径支持查看完整值与复制，失败和不完整状态可见。
4. **连接、模型与诊断**：连接前可编辑 Curry 地址端口、ONNX 启用／文件／通道；连接后锁定状态与原因可见。诊断、握手标签、单位和详细事件作为次级内容，不占据运行总览；错误摘要不因切页而消失。

800×600 时运行栏可以换行，但连接状态、控制状态、关闭自动控制和错误仍在首屏；页面内允许纵向滚动。默认 1000×720 时避免大面积空白。长中文、英文路径和较大系统字体应由布局自适应，不以固定宽度截断关键状态。使用原生窗口边框，避免自制标题栏和多层导航。

## 4. 视觉与交互规范

- 默认明亮中性底色与深色文字，蓝绿只标交互和正常过程，橙色标提醒，红色标故障／未确认停止。建议初版 token：背景 `#F7F9FB`、正文 `#223142`、主操作 `#116676`、故障 `#A02723`、提醒 `#8C5100`。这些前景在白色或指定浅色背景上的对比度需实测；本次计算的正文／背景为 12.55:1，三个强调色／白色分别为 6.59:1、7.48:1、6.38:1。文字目标至少 4.5:1；颜色之外始终有文字和状态词。[Windows 色彩指南](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/color)、[可读文字要求](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements)。
- 统一字体层级与控件高度，优先 Windows 系统字体及中文回退字体；不把重要中文说明压成小号灰字。保留可见焦点、Tab 顺序、快捷键和可访问名称；遵循[Windows 键盘与可访问性建议](https://learn.microsoft.com/en-us/windows/apps/get-started/best-practices)及[Qt 焦点规则](https://doc.qt.io/qtforpython-6.8/overviews/qtwidgets-focus.html)。
- 按钮有清晰主次：连接／启用是显式动作；断开、关闭自动控制、退出回放不与“打开／启用”共用同一视觉含义。状态色仅提示，不能把 `Start` UDP 已发送显示为设备已运行。Rally API 回复与物理输出验证始终分开；`FAULT/UNKNOWN` 与“请在 Rally/硬件侧独立停止”持续显眼。
- 设置区沿用 Issue 8 滚轮防误触：滚轮只滚动页面或打开的列表，不改选项／数值。弹出框、键盘、点击、回放导航仍可用。不要通过页签切换、悬停、动画或自动恢复上次状态触发刺激命令。
- 移除当前不准确的全局文案，如真实模式已可用时仍写“真实刺激未接入”；替代文案必须随实际模式与状态变化，并保留“API 确认不等于物理输出确认”。错误完整文本可滚动、选择与复制。模拟／真实、实时／回放、期望／确认的标签必须写全。

## 5. 关键场景与设计验收

验收画面至少覆盖：默认 NoModel＋模拟关闭；连接中／握手后短包累积；实时分期成功、失败和 NoModel；模拟自动决策；真实 `ARMED/IDLE`、`RUNNING`、`FAULT/UNKNOWN`（含独立停止提示）；录制／CSV 正常和失败；完整与不完整只读回放；长路径、长错误和 800×600。合成替身在截图中注明。每个场景核对控制可见性、状态词和禁用原因，不只看静态外观。

运行栏和各页面导航不得改变实时 session/generation 隔离、自动控制授权、Start/Stop 责任、记录单写者、回放只读与默认关闭状态。测试应证明仅切页和样式更新不会发送 Rally 请求；受控假端的实际启停仍走原有流程。Windows 原生鼠标、键盘、125%／200% 缩放和高对比度由可用的 Windows 桌面现场复核；macOS 离屏截图不算原生验证。
