## 2. 范式包与报文

范式包应包含一个版本化 `paradigm.json` 和其引用的各协议 JSON。范式内明确五期映射、`required_rally_base_protocol`、立即决策策略；协议内包含名称、版本、基础刺激/返回通道声明、Rally `SD/FR/FD/CHS` payload。加载时一次性解析所有引用，拒绝缺失、越界路径、重复或非法字段、非有限数、非法/重复通道、修改返回通道、与声明的同一基础协议不相容、未支持的决策策略。规范化 JSON 后冻结内存副本及 SHA-256；同一会话不因磁盘文件变化而改变。增加新范式只增加包，不复制状态机。

参考代码给出的 wire 形式是 UTF-8 `RealTimeControl `（末尾一个 ASCII 空格）加 JSON；成功只认精确 `RALLY_ERROR_SUCCESS`。已知 `RALLY_ERROR_*` 错误码为 API 拒绝，空、错编码、未知或来源异常为 unknown。继续接受 Rally 动态回复源端口，但校验来源主机与请求对应 socket，并保持有界等待、socket 隔离、单请求在途及额外 Stop 容量。实际字段单位、合法范围和设备能力不能从 Demo 示例推断；本地格式验证只证明软件格式。实验协议需附经核实的单位与时长换算信息，未核实前不能估算真实到期时刻或声称硬件时限已验证。

## 3. 阶段决策与请求顺序

范式 A：W→A，N1→B，N2→C，N3/REM→Stop。每个新的合格实时 ONNX epoch 立刻更新期望动作；无投票、连续 epoch 门槛、驻留时间或置信度阻断，置信度仍记录。年龄、完成时间、单调 block、session/generation 和回放隔离沿用 Issue 5。相同已确认协议 no-op。

- IDLE/STOPPED→X：发送 `Start Stim`，精确成功后再次检查当前会话、最新期望及年龄；若仍需刺激，**应用最新期望的协议**（A 在途时变 B 再变 C，应跳过 B）；`RealTimeControl X` 精确成功后才显示 `RUNNING(X)`。这是软件顺序操作，不是硬件原子事务。
- RUNNING(X)→Y：直接发送 `RealTimeControl Y`；只有精确成功才把确认协议改为 Y。切换期间显示 `SWITCHING(X,Y)`，不能预先显示 Y 正在运行。
- 任意在途期间只保存最新期望，不排无界命令队列；N3/REM、主动关闭、故障和 EOF 的 Stop 意图优先。未发送的 Start/Apply 可取消；已发送的请求等有界结果，不继续已过时的 Apply 链，必要时一次保护性 Stop。
- Start、Apply 拒绝/超时/未知：不自动重试；如果存在实际已发送的 Start 责任或上个协议可能仍活动，则一次 Stop 收尾，进入 FAULT/UNKNOWN。Stop 失败不循环重试，保留未确认物理状态。无 Start 证据的 IDLE 不发 Stop。
- `Start Stim` 到目标 Apply 确认期间仅能显示激活中/基础协议可能活动，不能显示目标协议已确认。记录两个确认时间及间隔；FR=30 秒与短暂基础输出仅是 Issue 的实验假设，尚无无受试者硬件时窗上限。

## 4. SD 到期的工程默认

仅当协议的 SD 单位和换算来源在范式包中显式提供并经本地验证时，按该值从协议 API 确认时刻计算**估计**到期时刻。到期立即撤销 `RUNNING(X)` 确认，显示 `EXPIRED/UNKNOWN`，解除自动控制并执行至多一次保护性 Stop（如果本应用仍有 Start 责任）。Stop 被 Rally 拒绝也不得解读为物理已停止。不会因同阶段下一 epoch 自动续期或重启；本次自动控制须由操作者核对 Rally/硬件状态后重新显式启用。无法确定单位的包不允许进入真实自动控制；合成测试用明确的测试单位验证计时。这个保守的软件恢复规则不声称 Rally 会在预估时刻物理停止，后续实验若需不同恢复策略应另立合同。

## 5. 会话证据

通过现有 SessionWriter 保存范式与所有协议的**规范内容快照**、版本、哈希、基础协议名称与人工确认；各 epoch 的模型/输入通道、分期和置信度、EEG 窗口起止及完成时刻；期望/no-op、请求、实际发送、原始回复/动态端口与 API 结果；Start→Apply 窗口、切换、持续时间及估计到期。记录 API 确认与物理验证为不同字段。沿用事件顺序屏障，使受理的必要 Stop 事件先于 `session_finished`；记录失败仍尽力 Stop 并报告缺失证据。旧会话格式可读，回放不会发送任何命令。真实材料、参数或物理刺激不由本合同自动授权。
