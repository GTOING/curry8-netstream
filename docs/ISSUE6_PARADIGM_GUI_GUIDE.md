# Issue 6 GUI 与范式包指南

本指南描述当前 GUI 软件行为，不授权真实刺激、实验或设备操作。完整字段和状态合同见 [Issue 6 工程合同](ISSUE6_PARADIGM_CONTRACT.md)；现有真实二值模式的 arming 边界见 [Issue 5 合同](ISSUE5_RALLY_ARMING_CONTRACT.md)。

## 选择与确认

“睡眠期决策与本机模拟”面板默认仍是本机模拟，自动决策关闭。真实控制模式下，“真实协议配置”可以选现有二值启停或版本化范式。范式模式还要选择包含 `paradigm.json` 和所引用协议 JSON 的目录。界面摘要显示范式名、版本、分类与包 SHA-256；加载器一次读取并验证所有内容，将规范快照冻结在当前 session 中。磁盘后续变化不会静默改变会话正在使用的协议。

启用前需要实时 Curry 会话、连接前显式选定 ONNX、完整的期别/结果年龄配置，以及操作者确认基础协议已在 Rally 中核对且当前未刺激。范式包必须被分类为可真实使用并具有可验证的 SD 换算；仓库测试包明确为 `synthetic/test-only`，所以会被拒绝真实 arming。加载或选择包本身不会发送命令；成功确认只进入 `ARMED/IDLE`，不发 UDP。

## 状态显示

每个新的合格 ONNX epoch 立即更新 latest desired：W→A，N1→B，N2→C，N3/REM→Stop。Start 成功后才继续 Apply 最新期望协议；两步均精确收到成功回复后才显示 `RUNNING(A|B|C)`。运行中切换直接 Apply，不先 Stop。界面分开展示期别期望、最新期望协议、API 最近确认协议、在途请求、估计到期、操作者确认和收尾责任。API 回复不代表已独立验证物理输出。

在途期间只保留最新期望；过时的中间协议不会排队补发。Stop 意图优先。启动或 Apply 被拒绝/未知/超时不会自动重试；有实际 Start 发送责任时最多执行一次保护性 Stop。SD 到期按包中明示且验证过的换算估计，届时撤销软件运行确认并显示 `EXPIRED/UNKNOWN`；它不证明硬件已停止，同阶段结果不会自动续期。

## 记录与回放

启用 P2 会话记录后，记录包含范式及 A/B/C 的规范内容快照、版本和哈希、基础协议声明、模型输入通道、阶段与置信度、期望/no-op、发送/回复、UTC 与 monotonic 时间及动态源端口。控制事件通过现有 SessionWriter 单写者；必要的 Stop 结果先于 `session_finished`。回放仅展示事件与状态，不连接 Rally、不运行策略，也不重发命令。保存关闭时不会创建这些会话事件文件。

## 参数与验证限制

仓库目前没有生产范式包；A/B/C 测试 fixture 的参数和 SD 单位仅为合成测试值，不可用于设备。生产 A/B/C 参数、基础协议、通道、电流/频率等设备限制与 SD 实际时间换算都尚未冻结。Issue 文字中的 FR=30 秒和 Start→Apply 期间短暂基础输出时窗只是实验假设，尚无硬件时间窗测量或批准，不是软件自动保证的时限。

本次 UI 截图及自动化验证来自离屏 Qt 与随机 localhost 假端。没有在 Windows 原生窗口、真实 Rally/`127.0.0.1:8801`、COM、电刺激硬件或受试者上执行验证；API 假端通过不能支持物理输出或研究效果结论。
