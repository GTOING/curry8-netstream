# P1 桌面与 Curry 脑电接入合同

日期：2026-09-15。决策主线程为 P1 发布的控制性约定，仅冻结本阶段范围；不冻结后续模型、刺激或同步合同。

## 1. 目标与边界

交付可由 `uv run --locked sleep-stim-controller` 启动的 PySide6/PyQtGraph 桌面程序。用户填写 Curry IPv4 地址与端口，主动连接后完成握手、接收和显示最新完整的 30 秒 EEG 块，支持断开和退出。

复用现有 Curry 解码与 DataBlock；UI 基于归档模板的布局结构提取到正式源码。模板原件保持不变。P1 不进行模型加载、自动分期、电刺激、记录/回放和跨设备同步。

## 2. 最小界面

- 顶部：程序名称或用途、统一连接状态摘要。
- 左侧固定区域：连接状态、连接/断开按钮、数据状态和持续错误提示。提示不随设置区域滚动消失。
- 左侧设置区域：IPv4 地址（默认 127.0.0.1）、端口（默认 4455），连接期间不可修改；可折叠会话元信息和诊断详情。
- 右侧：按服务器提供的 EEG 通道和顺序显示最新有效数据块。采用可滚动多通道图表，共享 X 轴、独立 Y 轴；无须一次挤入全部通道。允许执行者选择合理显示节流和绘图降采样，但不能改变原始 DataBlock。
- 显示块序号、start_sample、通道数、采样率、每通道采样数、持续时间和标签。
- 显示“模型未接入”“电刺激未接入”。本阶段不提供可操作的刺激、分期目标选择、暂停、打开/保存等未实现按钮。
- 初始图表为空；没有真实数据时不自动生成演示曲线。最后一块可以保留供检查，但断开/失败后明确标注为历史数据。
- 复用模板左右可调整分区、固定提示、滚动设置和折叠详情。默认窗口 1180×780，最小 800×600；关键按钮与错误信息在最小尺寸仍可访问。

## 3. 数据和显示语义

- 采用 Curry DataBlock.data[channel, sample]，小端 float32 解码和采样优先交织排列以现有协议实现为准。图表通道数不固定为五，不预设 250 Hz。
- 会话必须取得有效 BasicInfo 和 ChannelInfo 后才能交付数据；标签数量必须匹配实际 EEG 通道数，不合成缺失标签掩盖握手错误。
- P1 不做通道重排、重采样、滤波或额外缩放。当前材料不足以确认 Curry 数值单位，Y 轴显示“原始值（单位未确认）”，不得标为 μV。
- X 轴为该块内时间秒，x[k] = k / sample_rate_hz；另显示块起始样本号。不是本机墙钟，也不声称刺激同步。
- 交付前校验二维非空数组、通道/标签数、正采样率、数值有限及 30 秒长度（n_samples 与 30 × sample_rate_hz 一致）。实际不合格包停止本次接收并显示具体原因；不裁剪、补零或把非 30 秒包拼成合格包。
- 采样连续性采用现有检查；缺口/重复应清楚报错。旧库直接使用时行为可保留，P1 严格校验放在控制器接入边界。
- UI 仅保留最新有效完整块和必要诊断信息；绘图更新使用有界交接（至多一个待展示块，可替换过期显示），避免将每个大数组无限排入 Qt 事件队列。被替换的显示更新计数可诊断。该取最新策略仅用于 P1 展示，不能继承为后续推理/数据保存丢弃规则。

## 4. 生命周期和错误

- 明确 disconnected / connecting / streaming / stopping / error 状态；可单独描述等待元信息/首包。streaming 表示握手与推流请求已完成，不代表已收到有效 EEG。
- 仅 disconnected 或清理完成的 error 状态允许连接。connecting/streaming 允许断开；stopping 禁止重复操作。
- TCP 建连、握手、收包和解码在后台执行，Qt 主线程更新 UI。socket 与工作线程的生命周期有明确所有者。
- 空闲超时与失败分开：30 秒数据周期中短暂 socket timeout 继续等待，保留已收半包；不将 5 秒无数据判为失败。不预设握手总时限，但必须可取消。
- 默认连接超时 3 秒；在本地合成条件下，用户断开/关闭后后台清理在 5 秒内完成，包括等待首包与帧头/载荷半包状态。主线程不得阻塞等待网络；不能用强制杀线程实现取消。
- 正常断开尽力发送停止推流并释放连接；远端 EOF、连接失败、协议错误和非法数据保持错误详情，不当作正常收满或成功退出。停止推流不等于停止 Curry 采集/录制。
- 用户主动取消期间由取消产生的 socket 错误不作为异常故障显示。旧连接迟到回调不能覆盖新连接状态或数据。
- 关闭窗口沿用清理路径，不留下运行线程。清理未完成时保持可见状态，不伪造“已断开”。错误提示在下一次主动连接或明确清除前保留。

## 5. 对现有库的修改边界

优先公开接口与必要的小扩展；允许对 CurryClient 增加可取消接收、状态/会话通知、错误传递，或由适配器实现相同能力。避免复制协议解析器、依赖大量私有字段或运行 Demo 子进程。

改动要保留 CLI 和现有测试的正常使用方式。若为断连可观察性引入兼容参数，默认值/新调用入口写清楚；GUI 必须取得真实失败状态。禁止改变线协议字节布局、错误码、缩放或以伪造测试数据替换真实接入。

## 6. 验证与证据

- 必须覆盖根级现有 Curry 测试与新增控制器相关测试；完整相关测试集在最终改动上通过一次，不无变化重复运行。
- 以本机回环合成 TCP 服务经过真实握手、分帧和控制器接收入口验证两个连续 30 秒块；通道/采样率由 fixture 定义，仅是合成场景。
- 覆盖帧头和载荷分片跨超时、持续静默时取消、远端 EOF、不连续/非 30 秒/非有限值数据、重复连接保护、断开重连及关闭资源回收。复用 fixture，不给每个场景另建一套服务器。
- GUI 离屏检查布局、状态、图表、错误持续性；在有可用 GUI 工具时再进行 macOS 原生窗口检查。原生 GUI 不可访问时完成其他验证并准确记录限制，不虚报原生验收。
- 仅使用合成 localhost 服务，不连接用户真实 Curry 或 Rally，不运行归档电刺激脚本。验证 30 秒数据长度不要求每个合成测试实际等待 30 秒，但跨超时/取消必须真实覆盖相应行为。
